## 1. Что за проект

- **LPON.RU**: магазин и музейный каталог аудионосителей (кассеты, MD, винил, CD). История идёт с 2018 года, работа возобновлена в 2026-м.
- **Стек:** Python 3.12, Django 6.0+, Poetry (`pyproject.toml`), SQLite (`database/lpon-db.sqlite3`), django-filer, CodeMirror 6 в админке, nginx и Docker для прода.
- **Каталог кода:** `lpon_site/` (`manage.py`, приложение `frontend`, настройки в `lpon_site/lpon_site/`). Ключевые файлы: `frontend/models.py`, `frontend/admin.py`, `lpon_site/lpon_site/constants.py`.
- **Запуск:** README запуск не описывает; обычный путь для Django: `poetry install`, затем `poetry run python lpon_site/manage.py runserver`. Не проверялось.
- **Префиксы полей моделей:** `s_` (строка), `l_` (выбор), `k_` (связь), `j_` (JSON).
- **Ветка разработки:** `rework-2026`.

## 2. Три уровня данных (кратко)

1. Реляционная БД: ключи, цены, связи, статусы.
2. Универсальные JSON-метаданные: `TbItem.j_item_metadata` (характеристики модели) и `TbOffer.j_offer_metadata` (свойства экземпляра).
3. Специфика формата (тип ленты, длина, цвет корпуса и т. д.): лежит в тех же JSON, описывается конфигом.

## 3. Принятые решения (метаданные)

Подробности: `lpon--metadata-config.md`.

- Формат конфига: **TOML** (читается стандартным `tomllib`).
- Конфиг: единый **реестр имён ключей** JSON-метаданных. Админка строит по нему виртуальные поля, значения пишутся в `j_item_metadata` и `j_offer_metadata`.
- Конфиг растёт вместе с каталогом: правки только добавляющие, вместо удаления `deprecated`.
- Каталог: `config/metadata-toml/` (рядом с `config/nginx/`).
  - `default.toml`: базовый конфиг, **в git и в образе**. Черновик на 5 форм.
  - рабочие редакции (`ACTIVE`, `revisions/`, `journal.jsonl`): файлы, **не в git и не в образе** (правила в `.gitignore` и `.dockerignore`).
- Перезагрузка конфига через админку без перезапуска контейнера: процессы следят за `os.stat` файла `ACTIVE`.
- Переключатель формата в `TbItem`: ключ `media_format` в JSON, поле `s_item_type` в модель не добавляем.

## 8. Замечания, найденные по ходу

- В `.dockerignore` комментарии записаны в той же строке, что и шаблон (например, `.env  # ...`). Docker так не читает: такая строка воспринимается как шаблон вместе с комментарием и не совпадает с файлом. Скорее всего, `.env` и `database/` на самом деле не исключаются из контекста сборки. Нужно перенести комментарии на отдельные строки. Пока не исправлено, Docker пока не разбирался.
- В `.gitignore` склеены две строки: `*.sqlite3-journaldb.sqlite3` (должно быть две записи). Пока перекрывается шаблоном `*.sqlite*` ниже, но выглядит как опечатка.
- В боевом `docker-compose.prod.yml` команда запуска не стартует nginx и ссылается на файл `lpon-app--external-nginx.conf`, которого в репозитории нет (там `lpon--external-nginx.conf`). Найдено чтением, не запускалось. Подробности: `DEVOPS-COMPOSE-CI.md`, раздел 2.
- В `pyproject.toml` нет `gunicorn` (нужен для Docker-образа) и библиотек чтения Excel (нужны для парсинга).
- Папка `datasources/` (CSV и zip Discogs, около 1 МБ) не отслеживается git и не исключена правилом в `.gitignore`; решить, хранить ли её в репозитории.
